# Changelog

## 0.8.0
- Relicensed EventCore's own code under the **MIT License**. End users must still own Cyberpunk 2077 **and Phantom Liberty** to run it with the game; no CDPR assets are included in this repo.
- Client inkWidget pipeline only: dist/eventcore-hud.zip (preload_mod). No web vitals UI. RPCore server optional; seedDefaults false.
- EventView (LTE + per-player missions, target player/nearest/group/all).
- Added EventView (LTE schedules + per-player missions, target player/nearest/group/all). See docs/eventview.md.
- `server/hud.lua` and the RPCore `Hud*` exports are unchanged and still supported. The new native HUD code sits beside them.
- Added `shared/native_registry.lua` (generated by `tools/gen_native_registry.py` from the game's REDscript dump and `metadata.json`): the `inkHUDLayer` and other ink layers, all native ink widgets, all 1,099 controllers (113 HUD controllers) and all 124 blackboard definitions.
- Added `client/native_hud.lua`: `EventCore.NativeHud.Caller(name)` returns a show/hide caller for every layer, widget and HUD controller in the registry, `Call({ target|group, action })` returns a structured result, and a `NativeHudCall` export. Only `health`, `stamina`, `weapon` and `speedometer` are known to be accepted by `Open77.hud.setVisible`; every other name is passed through and the result reports whether the host accepted it. Blackboards are listed but report `no_host_api`: no Open77 call for them is documented.
- Added the server HUD test bench (`server/hud_bench.lua`) and a "HUD test bench" section in the admin panel: send a call to any player, run it locally for comparison, run `inkHUDLayer` or all-controller sweeps, schedule timed steps (server validates, client plays them back) and watch every result in a live event viewer. Commands: `/eventcore.hud.test`, `/eventcore.hud.schedule`, `/eventcore.hud.log`, `/eventcore.hud.cancel`. Global admin only; see `docs/native-hud.md`.

## Unreleased
- Docs: game-ownership notice (Cyberpunk 2077 + Phantom Liberty); project code is MIT as of 0.8.0.
- Docs: refreshed `AGENTS.md` and `docs/IMPLEMENTATION_STATUS.md` after the 2026-10-11 in-game test. Removed the outdated 0.6.5/0.3.3 test-bench diagnosis, "uncommitted" and "not deployed" notes, and the stale test-server path.
- Docs: `open77_chat` must be listed in `resources.load` (the manifest does not enforce it); documented the symptom when it is missing.
- Docs: documented where command output appears (chat vs client log vs server console) and that a nested `rpcore/` folder must not exist inside the EventCore folder.
- Docs: recorded the operator-reported known issues (vanilla health and "lifelihood" bars not displaying properly; wider screen aspect ratios). They are not EventCore configuration problems.
- Added `server/hud.lua`, EventCore's controller for the RPCore HUD. RPCore only accepts HUD writes from EventCore, so EventCore now owns them: `HudSetVital`, `HudSetPsychosis`, `HudForceTier`, `HudReleaseTier`, `HudSetBarVisible`, `HudSetElement`, `HudResetElement`, `HudResetElements` and `HudGetStatus` exports (callers: `rpcore`, plus `EventCore.HudCallers`). Calls are queued and made from one worker thread; remembered vitals and element overrides are replayed on join and whenever RPCore restarts. New joiners get baseline vitals (`EventCore.HudConfig.seedDefaults`) so the bars appear.
- Added admin test commands `/eventcore.hud.vital`, `.bar`, `.tier`, `.element`, `.reset` and `.status`.
- Added client bridge request IDs and bounded per-player replay protection so a retry with the same action and payload reuses the completed result instead of invoking the provider twice.
- Added EventCore 0.7.0's paired typed bridge: explicit resource/action allowlists, Open77 callback transport in both directions, caller-derived provider ownership, payload/result caps, per-player rate limits, and structured action results.
- Added Warden-gated `/eventcore.bridge` diagnostics plus opt-in, payload-free success logs for bridge registration and action outcomes (`EventCore.BridgeDebug` in `server/whitelist.lua`).
- Hardened the provider catalog: services now require an EventCore manifest dependency and a resource-owned ID prefix, and only the same resource generation can unregister its descriptor.
- Published a small client bridge library for adapters and documented HUDitor as a first-party client layer in the paired EventCore/RPCore stack.
- Replaced only Open77's chat presentation while keeping its chat resource active for help text, command results, server output, and suggestions.
- Preserved command error styling and message templates in EventCore's chat feed.
- Added Open77 command suggestions and native server/resource message forwarding to the EventCore chat.
- Tightened the top-left chat typography and layout to fit four recent messages below the input.
- Documented EventCore's scoped-storage role in native game-map integrations: persist pin definitions while the game renders the map and blips.

## 0.6.0

- Added an EventCore-owned, skinnable in-game chat surface and T key mapping.
- Added server-side chat validation, a bounded send rate, and client fan-out.
- Routed slash commands through Open77's existing authenticated command dispatcher; command ACLs and resource command registrations remain in force.

## 0.5.0

- Added a server-only structured storage gateway so approved resources can persist their own data without direct SQL access.
- Isolated resource and per-player records by the actual calling resource; callers cannot select another resource's namespace or submit SQL.
- Added bounded key listing, payload limits, atomic batches, schema initialization, and write audit events.
- Documented the service ownership boundary: use a domain resource's API when one exists and EventCore storage as the fallback. Shared RP services can build on EventCore contracts without combining mod inventories.

## 0.4.0

- Added an EventCore-owned administrator console and Warden-gated text commands for opening it, listing global admins, inspecting player roles, and viewing runtime services and event handlers.
- Added a player roster, quick-action bridge, and Warden-checked `admin.*` command console; Open77 rechecks each command at execution.
- Added read-only event-handler diagnostics and the service directory to the admin console.
- Kept Warden as the sole authority for assigning global roles.

## 0.3.1

- Added trusted, read-only ACL role queries for player tools: `IsAdmin`, `GetPlayerRoles`, and `GetOnlineAdmins`.
- Defined global admin as Open77's reserved `admin` or `owner` role; scoped staff roles do not count as global admin.
- Declared `acl.read` for EventCore. Role assignment remains owned by Warden and the Open77 ACL.
